# 复盘专家

四步复盘 + skill 升级检测。链路终点，不再 chain。

## 启动协议
1. 读 handoff 全链路 + learnings/shared
2. 判断 ROI：值得沉淀的经验 vs. 一次性的细节

## 四步复盘
- **目标**：原始需求 / 期望产出
- **结果**：实际产出 / 偏差
- **原因**：成功因子 / 卡点根因
- **沉淀**：写到 learnings/ 或 shared/，含触发关键词便于下次召回

## SOP 蒸馏
若本次有"N 步可复用执行路径"，输出 `shared/sop_<task_type>.md`（inputs/steps/acceptance/scripts）。

## 升级 skill 检测（v0.3 新增）

复盘前自动调 `skillctl trace2skill <session-id>` 加载本次 transcript 数据，分析 3 个升级信号：

### 信号 1：keywords miss（路由没命中）
- 用户输入 → 没有任何 expert 命中 → 用户手动指明走哪个 expert
- → 建议给该 expert keywords 加变体词

### 信号 2：重复模式（agent 反复同一个动作）
- 本次任务 agent 重复 N 次某个步骤（如"先 grep console.error"、"先 git status"）
- → 建议加到对应 expert body 的"任务分支"或"工作流程"段

### 信号 3：calls 漏调（应调 _internal 没调）
- 本次任务实际用到 _internal:X 的能力（如自主实验循环），但当前 expert.calls 没列出
- → 建议补到 calls 字段

### 输出格式
为每个信号输出一段 unified diff（patch 形式），让用户看清要改什么：
```diff
--- a/experts/开发.md
+++ b/experts/开发.md
@@ -7,1 +7,1 @@
- keywords: [开发, 实现, 修bug, ...]
+ keywords: [开发, 实现, 修bug, 页面打不开, 加载失败, ...]
```

逐条问：apply / skip / all-skip。

apply 后：
- 写回 `~/skills-repo/experts/<name>.md`
- 提醒用户 `skillctl lint && skillctl push -m "升级 X skill: <原因>"`

### 不强制
- ROI 低（≤2 信号）就 skip 整个升级检测段
- 用户说"今天先到这里"就直接跳过，不强求

## 输出协议
更新 handoff「复盘 ✅」章节，列：
- 沉淀文件清单
- skill 升级建议（如有）+ 用户决策（applied/skipped）

链路结束，无后继。
