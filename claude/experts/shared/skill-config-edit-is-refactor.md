---
name: 改 skill / hooks / settings / 规则类文件 = 重构，不是调研
date: 2026-04-18
type: antipattern
---

当用户说"加强 X 专家的 skill" / "改 settings" / "优化 hooks" / "让 X 判断更准"时，主 Agent 常错判为"调研/选型/方案对比"，只跑 调研→复盘，把真正的落地（编辑文件）卡在"等用户确认"上。这是**路由过保守**反模式。

**Why:**
- "调研/选型"的典型特征是**输出物是方案或文档**；"重构"的特征是**输出物是改动后的文件**。"加强 skill" 明确是后者——目标文件就在 `~/.claude/commands/experts/*.md`，不落地 = 没做事
- 调研专家自设 confirm gate（"等用户确认再落地"）违反路由规则 3 "链式自动流转，中间不停顿"。这个 gate 源于主 Agent 对"改全局配置"的本能谨慎，但用户已在 memory 里显式声明过"不要 yes/no"和"S2 起自动判断不再问"
- 真实案例：2026-04-18 用户让"从 GitHub 找测试/bug 项目加强专家 skill"，走了两轮调研→复盘，文件一个字没改，用户问"为什么刚才没自动更新"才补跑开发→审查→交付，链路走了两遍

**How to apply:**
路由判断时，遇到以下任一特征就走 **重构链路**（调研→开发→审查→交付→复盘），不是调研链路：
1. 任务文本里出现 "加强/优化/改造/升级 + 某个已存在的 skill/agent/规则文件"
2. 动作目标是 `~/.claude/**/*.md`、`settings.json`、`hooks`、`keybindings.json` 等配置文件
3. 前一轮已做过调研且产出了 "影响范围：xxx 文件"，本轮应直接进开发而非再调研
4. 用户说 "落地" / "应用上" / "加上去" / "写进去"

识别 confirm gate 自检：handoff 里写 "等用户确认再..." 时立刻追问自己——这个"确认"是用户真没说清楚，还是我在给自己找不动的理由？后者 → 删掉 gate 直接继续。
