站在攻击者角度，推演"从 **未认证外部** 到 **拿到目标资产** 需要走几步"。AISI 的 TLO 评估里 Mythos 能完成 32 步中的 22 步平均、3/10 次全通关；人类基准约 20 小时。Mythos 做得到的不是单步强，是**每步可分解验证** + **失败后换路线**。

**Why：**
- 传统代码审查按文件线性读，找单点问题；攻击者按**资产**反向规划路径
- 多数 bug 链里的每一步单独看都"不是 bug"（预期功能、兼容保留、debug 接口）—— 只有攻击路径视角能把它们串起来
- 这个视角能一次性识别防御深度不足（只要一步被突破整条链就通），比逐点审查信息密度高得多

**How to apply（审查时强制走一遍）：**

1. **定义攻击目标**（2 行）：
   - 资产：`/admin` 接口 / 数据库 user 表 / OSS 私钥 / 企业内网 / 其他用户数据
   - 起始 privilege：`未认证外部` / `普通用户` / `内网已落脚` / 其他

2. **推演路径（至少 3 条候选，每条 ≤7 步）**：
   ```
   路径 A: [起点] → step1: 扫 /api 发现 X → step2: X 回显 Y → step3: Y 用于 Z → [资产]
   路径 B: ...
   路径 C: ...
   ```

3. **逐步验证每步的前提条件**：
   - 这一步依赖什么？（配置、版本、时序、权限）
   - 代码里是否真有这条件？grep / 读配置验证
   - 如果 **只有一层防御** 在拦这一步 → 高危
   - 如果 **两层独立防御** 都在拦 → 中低危

4. **找"单点失败"**：整条链里只要一步被突破就通的，就是优先修复目标。多数真实高危漏洞都是这种。

5. **记录到 finding**：
   ```
   [路径 A, step 2] 攻击者只需 … 即可跳到 step 3，因为 … 没有 …
   PoC: <具体 curl / payload>
   建议：在 step 2 处加第二层独立防御（不是加强 step 1）
   ```

**不适用场景：**
- 纯后台 CLI 工具 / 内部 lib / 无信任边界的纯算法模块
- 已经做过完整威胁建模的系统（别重复做）

**成本提醒：**
推演 3 条路径 × 7 步 = 约 20 分钟人工 / 5 分钟 LLM。比穷尽式审查效率高 5-10 倍。
