---
name: 派子 agent 先盘点再补齐的协作范式
date: 2026-04-17
type: pattern
---

用户给"把 X 做完"类模糊大任务时，主 agent 的第一步不应该直接动手写代码，而是派子 agent 做 *当前完成度盘点*。

**Why:**
- 大项目里"还没完善"的说法常常高估了缺口。flower 项目本次管理端被预判为"空壳"，实测 8 个模块全部真实可用，只需补 2 个新功能
- 盲目"从零补全"会撞车、会重写已 work 的代码、会破坏用户已经调通的部分
- 盘点表（✅/🟡/🔴/❌）能在 1 个 agent 轮次内把整个模块的状态压成 20 行，之后的决策成本降到最低

**How to apply:**
派给子 agent 的 prompt 结构：
1. **第 1 步：盘点** —— Read + Grep 各主模块，产出 markdown 表格，每行：模块｜文件｜状态｜说明
2. **第 2 步：只补 2-3 个最关键缺口** —— 按"论文/需求明确承诺 & 当前缺失 & 改动成本低"三条优先级挑，不要贪多
3. **第 3 步：验证 + commit** —— 真实跑构建/冒烟 + 中文主题 commit，不 push
4. **第 4 步：回报含"剩余 top 3 缺口"** —— 交还主 agent 决定下一轮是否追击

硬约束要写明：不改 UI 视觉、不做无关 refactor、不动长任务状态文件。

效果：flower 项目 4 轮推进 + 审查闭环，每轮一个子 agent 全程自治（盘点→改代码→验证→commit），主 agent 只做验收和续推，整体 7 commit / 2009 行变更。
