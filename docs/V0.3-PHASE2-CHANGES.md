# v0.3 Phase 2 — V3 路线图清空

trace2skill 之后，把 V3 路线池剩 6 项一次性收口。

## 新能力

### 1. `skillctl status` — 调用率监控
扫最近 N 天 transcript，统计 expert 调用频次 + 路由覆盖率。

```bash
skillctl status --days 7
# === skillctl status (7 days) ===
#   sessions:        12
#   user prompts:    87
#   expert coverage: 67% (8 / 12 sessions)
#
# === expert 调用频次 ===
#   experts:开发              5 sessions
#   experts:复盘              3 sessions
#   ...
```

健康提示：≥80% 健康 / 50-80% 中等 / <50% 警告（建议跑 trace2skill 找 keywords miss）。

### 2. `skillctl chain show` — DAG 去重
`experts:调研 → 设计 → 开发 → ...` 多路径汇合到"复盘"时不再重复打印整棵子树，标记 `(已展开过，省略子树)`。

### 3. router-v2.sh — keywords fuzzy 匹配
两轮匹配策略：

| 轮 | 算法 | 何时用 |
|---|---|---|
| 1 | 字面子串匹配（精度高）| 首选 |
| 2 | 子序列匹配（kw 字符按顺序出现在 input）| 第 1 轮 miss 时兜底 |

例：keywords 含 `加功能`，用户输入 `加个新功能` → 子序列匹配命中（fuzzy）。

精度 vs 召回 tradeoff：fuzzy 仅在 keyword 长度 ≥3 时启用（避免单字误判）。

### 4. Codex adapter — 第二平台落地
`skillctl sync --target codex` 把 canonical 渲染到 `~/.codex/agents/<ns>/<slug>.md`：

```
~/.codex/agents/
├── experts/
│   ├── 调研.md / 设计.md / ...
└── _internal/
    ├── autoresearch.md / ...
```

输出格式：`# {name}` + `> {description}` + body。**Alpha：不渲染 router/chain，仅做 markdown agent description**。Codex 的 hook / 触发器机制 V4 实现。

### 5. tests/e2e/full-cycle.bats — 端到端测试
6 用例覆盖 init → lint → sync → chain show → chain list → status。

bats 总数：unit 5 + e2e 6 = **11 用例全过**。

### 6. GitHub Actions CI
- `.github/workflows/shellcheck.yml` — 推送 + PR 时跑 shellcheck（advisory）+ bash -n（hard fail）
- `.github/workflows/bats.yml` — 装 yq+jq+bats 跑全部测试

## Bug 修复

### bash 3.2 兼容
macOS 默认 bash 3.2 不支持 `declare -A` 关联数组。修：
- `cli/cmd/chain.sh` VISITED 改用字符串 + `grep -F`
- `cli/cmd/status.sh` expert_count 改用临时文件 + `sort | uniq -c`

### sync.sh `set -o pipefail` + SIGPIPE
v0.3 trace2skill 同款问题：`xargs ls -t | head -1` 在 pipefail 下被 SIGPIPE。已在前文修复。

## 已知 caveat

- `skillctl status` 扫到的 expert 名含历史 transcript 杂质（`experts:复盘\n` 这类被 grep 扩出的 token）— alpha 阶段忽略，V4 加严格过滤
- Codex adapter 仅渲染 markdown，不渲染 hook / 强制路由（Codex 平台机制不同，需独立设计）
- fuzzy 匹配可能误判（"调研一下方案" 的"一下方"理论上能匹配某 expert 不相关的 keyword 子序列）— 实战观察后再调
