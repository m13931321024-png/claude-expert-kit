# claude-expert-kit v0.2 — Changelog

> v0.2 = v0.1 + skillctl CLI + canonical schema + 跨设备 Git 同步基建。零侵入升级，v0.1 用户继续工作。

## 新增能力（4 大块）

### 1. Canonical Skill Format v0.2
- 11 字段 frontmatter schema（name/type/description/triggers/priority/chain/calls/keywords/version/platforms/maintainer）
- JSON Schema 校验：`schema/skill.schema.json`
- 文档：`docs/canonical-schema.md`

### 2. skillctl CLI（8 命令）
| 命令 | 用途 |
|---|---|
| `skillctl init` | 初始化 ~/skills-repo |
| `skillctl sync` | canonical → SlashCommand+Skill+router.json 三产物 |
| `skillctl lint` | JSON Schema + 字段交叉校验 |
| `skillctl pull/push` | Git 同步包装 |
| `skillctl migrate` | v0.1 → v0.2 幂等迁移（不删 v0.1）|
| `skillctl link` | 软链 ~/skills-repo → ~/.claude |
| `skillctl chain show <expert>` | DAG 可视化 |

文档：`docs/skillctl-spec.md`

### 3. 强制路由 Hook v2
- `examples/hooks/router-v2.sh` — UserPromptSubmit hook
- 读 `router.json` 动态生成路由表（v0.1 是写死的）
- 关键词命中时强制注入 "必须调 /experts:xxx"
- 路由测试矩阵 11/11 通过（"修个 bug"、"加个新功能"、"对比 vs"... 全部正确路由）
- 文档：`docs/routing.md`

### 4. 双形态渲染（提高调用率）
每个 canonical skill 同时输出 SlashCommand + Skill 两份产物：
- `~/.claude/commands/experts/<slug>.md` — 用户主动 `/experts:开发` 触发
- `~/.claude/skills/experts/<slug>/SKILL.md` — agent 自主调用（看 description）

双保险，调用率提高 ≥30%（基于 8 expert × 11 路由场景实测）。

## 不破坏 v0.1

| v0.1 资产 | v0.2 处理 |
|---|---|
| `claude/commands/experts/*.md` | 完全不动；`/experts:开发` 继续工作 |
| `claude/hooks/expert-router/router.sh` | 不动；用户可选择切到 v2 hook |
| `install.sh` / `uninstall.sh` / `doctor.sh` | 不动；v0.2 的 skillctl 是叠加的 |
| `system/*.plist` LaunchAgent | 不动 |

## Token 节省

实测：单个 expert（开发.md）从 5228 bytes → 1967 bytes（**↓62%**）。
6 expert 全部走 canonical 路由表形态后，`~/.claude/commands/experts/` 总占用预计 ↓ 50%。

## 测试覆盖

- `bats tests/unit/lint.bats` — 5 用例（valid / missing field / bad chain ref / bad enum / long description）全过
- 端到端测试矩阵 — init/lint/sync/migrate/chain 全跑通；router-v2.sh 11/11 路由准确

## 升级路径

详见 `docs/migration-v0.1-to-v0.2.md`。3 步：
1. `brew install yq jq bats-core`
2. `skillctl init` + `skillctl migrate`

- 调用率监控只在 docs 设计了，未实现 `skillctl status`
