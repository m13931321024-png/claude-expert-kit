# v0.3 — trace2skill：复盘自动检测 skill 升级建议

## Why

加州 v0.2.1 后的设计反思：用户问"我怎么升级 skill"——之前的答案是"手动改 frontmatter"，没有闭环。1 号说"我用 AutoReSearch + 定时任务升级"——但 skill 本身怎么改没回答。

**真正的闭环**：你跑任务 → 任务 trace 是天然反馈信号 → 自动从 trace 提炼"该改哪条 skill" → 复盘 expert 顺手做。**不需要新命令、不需要定时任务、不打扰用户工作流**。

## What

### 1. `experts:复盘` 增加"升级 skill 检测"段
每次走到复盘自动检测 3 个升级信号：
- **keywords miss**：用户输入未命中任何 expert keywords → 建议补 keywords
- **重复模式**：transcript 中重复 ≥3 次的步骤 → 建议进 expert body
- **calls 漏调**：实际用到的 _internal:* 不在 calls 字段 → 建议补 calls

每条信号输出 unified diff，逐条问 `apply / skip / all-skip`。

### 2. `_internal:trace2skill` 新增
被复盘 expert 调用的内部工具 skill，封装"分析 trace + 输出建议"逻辑。

### 3. `cli/cmd/trace2skill.sh` 命令
不做 LLM 分析（agent 已在 LLM 上下文）；本工具仅做：
- 找到 session transcript 文件
- 提取最近 N 轮关键事件（默认 N=50）
- 提取本次涉及的 skill frontmatter
- 输出统一 JSON 给 agent 解读

```bash
skillctl trace2skill [--session ID] [--last N]
```

### 4. fix: SIGPIPE on `xargs ls -t | head -1`
`set -o pipefail` 模式下 `head` 关闭管道会让 xargs 被 SIGPIPE，导致脚本 exit 1。修：临时 `set +o pipefail` 包住该段。

## 设计哲学

**为什么是复盘的内置能力，不是独立命令**：

| 设计 | 体验 |
|---|---|
| 独立命令 `skillctl trace2skill` | 用户得记得调 → 99% 不会想起来 → 升级停滞 |
| 融入复盘 expert（采纳 ⭐）| 链路终点天然到达 → 升级建议作为复盘副产物 → 0 额外动作 |

**不必触发新 skill 升级 skill**——复盘本来就是经验沉淀的环节，让它顺手把"经验沉淀到代码"也做了。

## 已知 caveat

1. trace2skill 仅做"数据加载 + 提示"，**不做 LLM 分析**——分析靠复盘 expert 的 agent 上下文做。这个设计避免了 hook 调外部 LLM API（成本+延迟+复杂度），但要求复盘 expert 真的按 prompt 指引去分析（依赖 agent 自觉）。
2. 信号检测 3 类是**启发式**，不全。后续可能加：循环深度（agent 反复改同一文件）、错误恢复模式、用户主动指明 expert 的频次。
3. 不自动 apply 改动——必须用户 confirm。原因：trace2skill 是建议器不是决策器。
4. 跨 session 趋势分析未做（"某 expert 一直 keywords miss"是收敛性问题，需要扫多个 session）。V4 待办。

## 升级路径

v0.2.1 → v0.3：跑 `skillctl migrate --force` 即可（migrate 命令本身没变；examples/ 更新后 sync 即生效）。

加州个人用户：
```bash
cd ~/skills-repo
git pull   # 拉本仓库 examples 最新版
cp /path/to/claude-expert-kit/examples/canonical-skills/experts/复盘.md experts/  # 用新版覆盖
cp /path/to/claude-expert-kit/examples/canonical-skills/_internal/trace2skill.md _internal/  # 加新 internal
skillctl lint && skillctl sync && skillctl push -m "升级到 v0.3 复盘+trace2skill"
```
