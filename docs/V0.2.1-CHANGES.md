# v0.2.1 — Schema 简化：合并 triggers 到 keywords

## Why

1 号挑战："我都 keyword 可以匹配 skill 了，咋还要给你写入字典"——v0.2 schema 同时存在 `triggers`（字符串，hook 字面匹配）和 `keywords`（数组，V3 embedding）两个字段，**本质都是"路由关键词"**。重复 = DRY 违规 = 用户复制时困惑"我该写哪个"。

## What

把 `triggers` 合并进 `keywords`：

| v0.2.0 | v0.2.1 |
|---|---|
| `triggers: 修bug\|修复\|报错` | (删除) |
| `keywords: [编码, 多Agent]` | `keywords: [开发, 修bug, 修复, 报错, 编码, 多Agent, ...]` |

## Breaking changes

- ❌ 删除 frontmatter `triggers` 字段（schema 不再接受）
- ❌ `router.json` 里的 entry 字段改名 `triggers` → `keywords`
- ✅ `skillctl migrate` 自动把 v0.1/v0.2.0 的 triggers 合并到 keywords（用户无需手工迁移）
- ✅ `router-v2.sh` 兼容旧 router.json（先读 keywords，没有 fallback 到 triggers）

## 升级路径

```bash
cd ~/skills-repo
# 用 yq 一行合并 triggers 到 keywords，删除 triggers
for f in experts/*.md; do
  # 此处略，跑 'skillctl migrate --force' 也可（重做迁移）
done
skillctl lint && skillctl sync
```

OSS 上 v0.2.0 → v0.2.1 用户：跑 `skillctl migrate --force` 即可。
